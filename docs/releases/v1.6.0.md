# ChaosSQL v1.6.0 Release Notes

**Release Date:** September 23, 2026
**Tag:** `v1.6.0`
**Theme:** Reliable ChaosSQL Cloud ingestion, multi-tenant control plane, and managed deployment

---

## Summary

v1.6.0 makes ChaosSQL Cloud dependable enough for early adopters. Ingestion is
now transactional and idempotent, baselines compare real commits with a stable
scenario fingerprint, hosted payloads carry metadata only, and one server can
host several isolated organizations. A managed deployment with continuous
backups and a tested restore procedure is included.

The full list of changes is in [CHANGELOG.md](../../CHANGELOG.md#160---2026-09-23).

## Highlights

- **Reliable ingestion.** Run, findings, baseline decision, stored response,
  and webhook outbox commit together. Each execution has its own idempotency
  key: identical retries return the original response and conflicting content
  returns `409`.
- **Trustworthy regression detection.** Baselines use the real commit time of
  the SHA and a fingerprint computed locally from the scenario semantics
  (not the PRNG seed). Different fingerprints are never compared.
- **Privacy by construction.** The client uploads metadata only: no SQL,
  parameter values, schema, table names, traces, or reproduction code.
- **Multi-tenant control plane.** `chaossql server org create|list|set-plan`
  provisions isolated organizations with a one-time owner token.
- **Plan retention** (opt-in) deletes history outside each plan's window while
  keeping baseline runs and pending alerts.
- **Managed deployment.** `deploy/fly/` and `docs/managed-deployment.md`:
  API and dashboard on one origin, Litestream replication, automatic restore on
  an empty volume, and a restore drill that never writes to the backup.
- **GitHub Action.** Inputs are passed through environment variables, and the
  step exposes `cloud-run-id`, `cloud-run-url`, and `is-regression`.

## Upgrade notes

- **Database migrations run automatically** on the first start of
  `chaossql server` or `chaossql-server`. Back up the SQLite file first (see
  `docs/self-hosted.md`). Commit times recorded by older versions were upload
  times; the migration clears them so new baselines are not blocked.
- **`server create-token` requires an existing organization.** A mistyped
  `--org` now fails instead of creating a tenant. Use `server org create` to add
  organizations.
- **Retention is off by default.** Enable it with `--enforce-retention` only
  after taking a backup; deletion is permanent.
- **Run links changed** from `/#/dashboard?run=<id>` to `/dashboard?run=<id>`.
  Old links still work: the site migrates hash URLs on load.
- **Action pin:** update workflows to `bregaldahq/chaossql@v1.6.0`.
- **Container images:** no image is published to a registry for this release.
  The Helm chart's default `ghcr.io/bregaldahq/chaossql-server:1.6.0` must be
  built and pushed by the operator, or overridden with `image.repository` and
  `image.tag`.

## Verification

`make verify` (harness, lint, race-enabled tests, WASM, frontend, and language
checks) passes on the release commit. The managed image was verified end to end
against disposable object storage: startup guard without backups, same-origin
dashboard, tenant provisioning, restore drill, and restore onto an empty volume.
