# ChaosSQL v1.4.0 Release Notes

**Release Date:** September 6, 2026  
**Tag:** `v1.4.0`  
**Theme:** Multi-Language Developer SDKs (Python & TypeScript), Embedded JSON IPC Engine & Transparent Database Proxy  

---

## Executive Summary

**ChaosSQL v1.4.0** broadens the reach of formal concurrency chaos testing across enterprise application ecosystems. While earlier versions required executing tests directly via the Go CLI or Go programmatic SDK (`pkg/chaostest`), real-world production applications interacting with transactional databases are overwhelmingly authored in **Python** (FastAPI, Django, SQLAlchemy) and **TypeScript / Node.js** (NestJS, Express, Prisma, Drizzle).

With v1.4.0, ChaosSQL delivers first-class, idiomatic developer SDKs for **Python (`chaossql-py`)** and **TypeScript / Node.js (`@chaossql/test`)**. Powered by an **Embedded Engine Binary Architecture** that communicates via high-performance bidirectional JSON streaming over standard I/O (`chaossql engine`), the SDKs completely bypass the Python Global Interpreter Lock (GIL), avoid cross-language FFI deadlocks, maintain memory isolation, and run with zero external runtime C dependencies (zero CGO).

Additionally, v1.4.0 introduces the **Layer-7 Transparent Database Reverse Proxy (`chaossql proxy`)** for non-intrusive concurrency fault injection on wire protocols, autonomous **Multi-Engine Differential Swarm Testing (`chaossql swarm`)**, and automatic **Synthesis of Zero-Dependency Regression Tests** in native Python and Node.js.

## Key Highlights & Capabilities

### 1. Embedded Engine Binary IPC (`chaossql engine`)
- **Zero-CGO Subprocess Streaming**: The core Go fuzzer distributes as a static, self-contained executable. Host language SDKs spawn the engine via standard I/O bidirectional JSON streaming.
- **GIL Bypass & Concurrency Purity**: Python cannot be deadlocked or slowed down by GIL contention during heavy concurrency interleaving loops; Go goroutines manage microseconds scheduling directly on native OS threads.
- **Deterministic IPC Protocol**: Consumes structured JSON scenario definitions over stdin and streams comprehensive results (detected anomaly classifications, failing invariant states, Adya cycle analysis, 1-minimal counterexamples, Mermaid sequence diagrams, and runnable repro scripts) over stdout.

### 2. Python SDK (`chaossql-py` / `pip install chaossql`)
- **Fluent `ChaosHarness` Builder**: Ergonomically mirrors native Go testing:
  ```python
  from chaossql import ChaosHarness

  harness = (
      ChaosHarness(driver="sqlite")
      .with_schema("CREATE TABLE accounts (id INT PRIMARY KEY, balance INT);")
      .with_seed("INSERT INTO accounts VALUES (1, 1000);")
      .with_invariant("balance_conserved", "SELECT balance FROM accounts WHERE id = 1;", "balance == 1000")
      .add_operation("withdraw", [
          "SELECT balance FROM accounts WHERE id = 1 -> cur",
          "UPDATE accounts SET balance = {cur - 100} WHERE id = 1",
      ])
  )
  harness.assert_no_anomalies(workers=2, iterations=20, seed=42)
  ```
- **Native Pytest Integration**:
  - Registered pytest plugin (`pytest11 = {"chaossql" = "chaossql.pytest_plugin"}`).
  - Test marker `@pytest.mark.chaossql(workers=..., iterations=..., seed=...)`.
  - Fixture `chaossql_runner` for declarative scenario validation.
- **Standalone Reproduction Export**: `harness.export_standalone_repro("repro.py")` generates a standalone script using standard library `sqlite3` and `concurrent.futures`.

### 3. TypeScript / Node.js SDK (`@chaossql/test` / `npm install @chaossql/test`)
- **First-Class TypeScript 5.0+ Typings**: Complete `.d.ts` declaration maps and strongly typed options.
- **Test Runner Agnostic**: Works out of the box with Vitest, Jest, and Node.js Test Runner (`node:test`):
  ```typescript
  import { test } from 'node:test';
  import { ChaosHarness } from '@chaossql/test';

  test('hospital on-call roster avoids write skew', async () => {
    const harness = new ChaosHarness({ driver: 'sqlite' });
    await harness
      .withSchema('CREATE TABLE doctors (id INT PRIMARY KEY, on_call INT); INSERT INTO doctors VALUES (1, 1), (2, 1);')
      .withInvariant('at_least_one', 'SELECT count(*) as cnt FROM doctors WHERE on_call = 1;', 'cnt >= 1')
      .addOperation('alice_leaves', [
        'SELECT count(*) as cnt FROM doctors WHERE on_call = 1 -> active',
        'UPDATE doctors SET on_call = 0 WHERE id = 1 AND {active > 1}',
      ])
      .assertNoAnomalies({ workers: 2, iterations: 20 });
  });
  ```
- **Automated Parameter Substitution**: Supports parameter maps, capture bindings (`-> var`), and inner arithmetic evaluation (`{var - 10}`).

### 4. Zero-Dependency Standalone Regression Test Synthesizers
- **Python Repro (`internal/reporter/repro_python.go`)**: Synthesizes zero-dependency Python scripts using standard library `sqlite3` and `concurrent.futures.ThreadPoolExecutor`.
- **TypeScript Repro (`internal/reporter/repro_ts.go`)**: Synthesizes standalone JavaScript / TypeScript test scripts using Node standard library `node:test` and `Promise.all`.
- **Reproduces Anomalies Deterministically**: Generated scripts execute independently in CI/CD without requiring the ChaosSQL binary or engine installed.

### 5. Layer-7 Transparent Database Reverse Proxy (`chaossql proxy`)
- **Wire Protocol Decoders**: Zero-CGO streaming decoders for PostgreSQL Wire Protocol 3.0 and MySQL Client/Server protocol.
- **Stochastic Micro-Jitter & Barrier Injection**: Stalls critical commit packets and introduces microsecond delays to expose concurrency race conditions.
- **Shadow Dependency Graph**: Real-time conflict edge detection ($ww, wr, rw$) and Adya anomaly classification.
- **OASIS SARIF 2.1.0 Security Reports**: Direct export for GitHub Code Scanning and SAST pipelines.

### 6. Multi-Engine Differential Swarm & DSL Mutator (`chaossql swarm`)
- **Differential Fuzzing**: Concurrently compares isolation behavior across SQLite, PostgreSQL, and MySQL.
- **DSL Scenario Mutation**: Micro-jitter perturbations, nested savepoint rollbacks, DAG step shuffling, and lock order inversion.

## Upgrade & Compatibility Notes

- **Full Backwards Compatibility**: All existing Go tests (`pkg/chaostest`), YAML scenarios, and CLI commands continue to work without modification.
- **Installation Requirements**:
  - Python SDK: Python >= 3.9, `pytest` >= 7.0.
  - TypeScript SDK: Node.js >= 18.0.0.
- **Engine Binary Auto-Discovery**: The SDKs automatically locate `chaossql` on the system `PATH`, from the `CHAOSSQL_BIN_PATH` environment variable, or in parent directories.
