Interface

Manual Completo da CLI & Todas as 12 Flags

Guia definitivo de uso da interface de linha de comando do ChaosSQL: documentação exaustiva de todos os 9 subcomandos, parâmetros posicionais, códigos de saída e a tabela completa das 12 flags de execução e exportação.

Arquitetura e Filosofia da CLI

A interface de linha de comando do ChaosSQL foi projetada para engenheiros de sistemas que exigem feedback rápido, controle granular e integração transparente com scripts de automação e pipelines de CI/CD. Baseada na biblioteca Cobra e formatada pelo framework Lipgloss, a CLI oferece saída rica em terminal ANSI, cores tonais suaves do Design System do Studio Bregalda e geração de relatórios padronizados (SARIF, JUnit, HTML, OTEL, Mermaid).

Tabela Mestra das 12 Flags de Execução e Exportação

Todas as flags podem ser passadas nos subcomandos run e demo, sobrescrevendo os valores correspondentes definidos no arquivo de especificação:

Flag Tipo Padrão Subcomandos Descrição Técnica
--seed uint64 0 (lê spec) run, demo, diff Semente estocástica do PRNG PCG64. Garante reprodução determinística bit-a-bit idêntica de qualquer anomalia.
--workers int 0 (lê spec) run, demo, bench Número de goroutines concorrentes executando transações simultâneas contra o banco.
--iterations int 0 (lê spec) run, demo Número total de transações/operações a serem agendadas na bateria de testes.
--export-sarif string "" run, demo Caminho de arquivo para exportar os achados no padrão OASIS SARIF v2.1.0 para o GitHub Code Scanning.
--export-html string "" run, demo Gera um relatório HTML interativo independente (~60KB) com swimlane Gantt e visualizador de grafos SVG.
--export-otel string "" run, demo Exporta o trace de execução como OpenTelemetry OTLP JSON para observabilidade no Jaeger ou Datadog.
--export-junit string "" run, demo Exporta os resultados em formato JUnit XML padrão para exibição em painéis de teste de CI/CD.
--export-summary string "" run, demo Exporta relatório formatado em Markdown compatível com $GITHUB_STEP_SUMMARY.
--export-mermaid bool false run, demo Exporta o diagrama de sequência temporal das transações conflitantes em formato Mermaid (trace.mermaid).
--export-repro bool false run, demo Sintetiza automaticamente um teste standalone em Go (repro_test.go) com a redução 1-minimal do ddmin.
--ui bool false run, demo Inicia automaticamente o servidor web visualizador de traces em 127.0.0.1:8090 e abre o navegador.
--json bool false run, demo, bench, diff, matrix Emite o resultado estruturado em JSON no stdout para integração com scripts externos.

Referência Exaustiva dos 9 Subcomandos

1. chaossql run <chaos.yaml>

Executa a bateria de testes de concorrência contra o arquivo de especificação informado:

# Execução padrão
chaossql run specs/banking_lost_update.yaml

# Execução com override de semente, workers e geração completa de relatórios
chaossql run specs/banking_lost_update.yaml \
  --seed=42 \
  --workers=8 \
  --iterations=50 \
  --export-sarif=reports/audit.sarif \
  --export-html=reports/report.html \
  --export-junit=reports/junit.xml \
  --export-repro \
  --ui

2. chaossql demo [cenário]

Executa uma das 10 demonstrações embutidas de anomalias de concorrência com terminal visual e delta-debugging:

chaossql demo banking       # P4 Lost Update
chaossql demo inventory     # A3 Inventory Oversell
chaossql demo hospital      # A5B Hospital Write Skew
chaossql demo financial     # A5A Financial Read Skew
chaossql demo auction       # G0 Auction Dirty Write
chaossql demo crypto        # G1c Circular Information Flow
chaossql demo flash_crash   # G1a Flash Crash Dirty Read
chaossql demo ticket        # G2 Anti-Dependency Cycle
chaossql demo deadlock      # G-DL Mutual Lock Deadlock
chaossql demo fk            # Foreign Key Cascade Deadlock

3. chaossql ui <trace.json>

Inicializa o servidor HTTP local para inspecionar um trace gravado previamente:

chaossql ui trace_dump.json --port=8090 --no-open
  • --port int: Porta do servidor HTTP local (padrão 8090).
  • --no-open bool: Não abre automaticamente o navegador padrão do sistema.

4. chaossql diff <spec.yaml>

Executa fuzzing diferencial cruzado comparando o comportamento de dois motores distintos com o mesmo workload e semente:

chaossql diff specs/lost_update.yaml \
  --driver-a=sqlite --dsn-a=":memory:" \
  --driver-b=postgres --dsn-b="postgres://user:pass@localhost:5432/testdb" \
  --seed=42

5. chaossql replay <result.json>

Exibe o swimlane cronológico de eventos com marcações de microssegundos no terminal:

chaossql replay result.json --max-events=100

6. chaossql bench

Executa microbenchmarks de vazão do PRNG determinístico e do detector de ciclos Adya:

chaossql bench --duration=3s --workers=8 --json

O benchmark atinge tipicamente mais de 13.9 milhões de operações/segundo em processadores modernos.

7. chaossql validate <chaos.yaml>

Linter estático que valida o esquema YAML, compila expressões dinâmicas de invariantes e verifica integridade referencial dos scripts SQL antes da execução:

chaossql validate specs/hospital_write_skew.yaml

8. chaossql init <caminho>

Gera o scaffolding inicial de um novo cenário com arquivos pré-configurados:

chaossql init novo_cenario --driver=postgres --name=auditoria_saldo --force

9. chaossql matrix

Gera uma matriz empírica completa baseada na taxonomia Hermitage (Martin Kleppmann), testando o banco alvo contra todas as 9 anomalias formais:

chaossql matrix --driver=postgres --dsn="postgres://user:pass@localhost:5432/testdb" --markdown

Códigos de Retorno do Processo (Exit Codes)

  • 0: Sucesso / Safe. Todas as transações foram executadas e nenhuma invariante foi violada.
  • 1: Violação Detectada / Anomaly Found. Pelo menos uma invariante falhou ou uma anomalia foi classificada (quebra builds de CI propositalmente).
  • 2: Erro de Configuração / Syntax Error. Falha de sintaxe YAML, arquivo ausente ou falha de conexão inicial.
