CLI Manual, Subcommands & All 12 Flags

Comprehensive manual for the chaossql command-line interface, detailed options, exit codes, and operational flags.

CLI Architecture & Design Philosophy

The ChaosSQL Command-Line Interface (CLI) is engineered for systems developers who demand rapid feedback loops, granular scheduling control, and frictionless integration with automated CI/CD pipelines. Built upon Cobra and styled with Charm Lipgloss, the CLI outputs expressive ANSI terminal diagnostics, soft tonal colors from the Studio Bregalda Design System, and exportable industry-standard artifacts (SARIF, JUnit XML, standalone HTML, OpenTelemetry OTLP JSON, and Mermaid sequence diagrams).

Complete Table of Execution, Scheduling & Export Flags

All flags can be passed to execution subcommands (run and demo), overriding corresponding parameters defined in the scenario specification file:

Flag Type Default Subcommands Technical Description
--driver string "" (reads spec) run, diff, matrix, init Target database engine driver (sqlite, postgres, mysql).
--dsn string "" (reads spec) run, diff, matrix Database connection string / Data Source Name for external database engines.
--config string "" run, validate Alternative file path to the YAML scenario specification.
--workers int 0 (reads spec) run, demo, bench Number of concurrent goroutines executing simultaneous transactions.
--duration duration 0s run, demo, bench Time-bounded fuzzing duration (e.g., 10s, 1m). Mutually exclusive with iterations.
--iterations int 0 (reads spec) run, demo Total transaction iterations scheduled across all workers during the session.
--jitter-min int 1 run, demo Minimum stochastic jitter micro-delay in milliseconds injected between SQL steps.
--jitter-max int 10 run, demo Maximum stochastic jitter micro-delay in milliseconds injected between SQL steps.
--seed uint64 0 (reads spec) run, demo, diff Deterministic PCG64 PRNG seed for bit-for-bit identical anomaly reproduction.
--pct-depth int 2 run, demo Maximum schedule priority change depth d for the PCT-SQL algorithm.
--ddmin bool true run, demo Enables or disables Causal Delta-Debugging counterexample minimization.
--output string "" run, demo, matrix Destination directory or base path for generated execution reports.
--port int 8090 ui, run Port for the local embedded HTTP trace visualizer web server.
--export-sarif string "" run, demo Exports findings in OASIS SARIF v2.1.0 format for GitHub Code Scanning.
--export-html string "" run, demo Generates a standalone, dependency-free interactive HTML audit report (~60KB).
--export-otel string "" run, demo Exports execution trace as OpenTelemetry OTLP JSON for distributed observability.
--export-junit string "" run, demo Exports execution results as standard JUnit XML for CI/CD test dashboards.
--export-summary string "" run, demo Exports a GitHub-flavored Markdown report directly to $GITHUB_STEP_SUMMARY.
--export-mermaid bool false run, demo Exports chronological sequence diagram of conflicting transactions (trace.mermaid).
--export-repro bool false run, demo Synthesizes an isolated Go regression test (repro_test.go) with ddmin reduction.
--ui bool false run, demo Automatically launches the embedded trace visualizer on 127.0.0.1:8090.
--json bool false run, demo, bench, diff, matrix Outputs structured machine-readable JSON to stdout for external automation scripts.

Exhaustive Reference of the 9 Subcommands

1. chaossql run <chaos.yaml>

Executes concurrency and invariant fuzzing against the provided specification file:

# Standard execution
chaossql run specs/banking_lost_update.yaml

# Execution with overrides and comprehensive multi-format report exports
chaossql run specs/banking_lost_update.yaml \
  --seed=42 \
  --workers=8 \
  --iterations=50 \
  --export-sarif=reports/audit.sarif \
  --export-html=reports/report.html \
  --export-junit=reports/junit.xml \
  --export-repro \
  --ui

2. chaossql demo [scenario]

Launches one of the 10 built-in reference demonstrations featuring terminal visualization and delta-debugging:

chaossql demo banking       # P4 Lost Update
chaossql demo inventory     # A3 Inventory Oversell
chaossql demo hospital      # A5B Hospital Write Skew
chaossql demo financial     # A5A Financial Read Skew
chaossql demo auction       # G0 Auction Dirty Write
chaossql demo crypto        # G1c Circular Information Flow
chaossql demo flash_crash   # G1a Flash Crash Dirty Read
chaossql demo ticket        # G2 Anti-Dependency Cycle
chaossql demo deadlock      # G-DL Mutual Lock Deadlock
chaossql demo fk            # Foreign Key Cascade Deadlock

3. chaossql ui <trace.json>

Starts the embedded HTTP web visualizer to inspect a previously recorded execution trace:

chaossql ui trace_dump.json --port=8090 --no-open
  • --port int: Local HTTP listener port (default 8090).
  • --no-open bool: Disables automatic launch of the system default web browser.

4. chaossql diff <spec.yaml>

Executes cross-engine differential fuzzing, comparing the runtime isolation semantics of two different database engines under identical workloads and seeds:

chaossql diff specs/lost_update.yaml \
  --driver-a=sqlite --dsn-a=":memory:" \
  --driver-b=postgres --dsn-b="postgres://user:pass@localhost:5432/testdb" \
  --seed=42

5. chaossql replay <result.json>

Renders a microsecond-accurate terminal Gantt swimlane from a recorded execution trace:

chaossql replay result.json --max-events=100

6. chaossql bench

Executes throughput microbenchmarks measuring deterministic PRNG generation and Adya cycle detection speeds:

chaossql bench --duration=3s --workers=8 --json

Benchmarks typically demonstrate throughput exceeding 13.9 million operations/second on modern multi-core processors.

7. chaossql validate <chaos.yaml>

Static linter that verifies YAML schema adherence, compiles invariant dynamic expressions, and validates relational referential integrity before runtime execution:

chaossql validate specs/hospital_write_skew.yaml

8. chaossql init <path>

Generates production-ready scaffolding for a new test scenario with pre-configured templates:

chaossql init new_scenario --driver=postgres --name=balance_audit --force

9. chaossql matrix

Executes an empirical matrix validation based on Martin Kleppmann's Hermitage test taxonomy, testing the target engine against all 9 formal isolation anomalies:

chaossql matrix --driver=postgres --dsn="postgres://user:pass@localhost:5432/testdb" --markdown

Process Exit Codes

  • 0: Clean / Safe. All transactions completed successfully and all invariant assertions passed with zero anomalies.
  • 1: Anomaly Detected / Violation Found. At least one invariant assertion failed or an Adya cycle was detected (intentionally fails CI builds).
  • 2: Configuration Error / Syntax Error. YAML syntax error, missing file, or initial database connection failure.
